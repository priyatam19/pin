So even though the signature is parse_packet(const uint8_t *data, size_t len), PIN’s current normalization path only knows how to emit protobuf schemas for structs/aggregates (or simple scalars) that represent the full logical input. A raw byte pointer plus a length parameter is treated as a parser function—which is precisely why we added the pass-through mode (--input-mode=raw). Proto mode can’t synthesize a meaningful schema for “opaque byte array + len” today, so normalization fails before fuzzing starts.

In contrast, the pass-through path works because it bypasses proto generation entirely, wires the libFuzzer byte stream straight into parse_packet, and lets you fuzz the parser directly.

Bottom line:

Structured proto mode: Can’t currently normalize uint8_t * + size_t; it requires a struct/aggregate input to map field-by-field.
Pass-through mode (--input-mode=raw): Designed for exactly this pattern and is the supported way to fuzz parse_packet.
